# nexus 2.0

Status: **proposed** (2026-10-03). Nothing here is built. Each section ends with
its decision; the open questions at the end need an answer before that section
starts.

## Why a major version

Go makes a major version expensive for users: the module path becomes
`github.com/paulmanoni/nexus/v2`, so every import in every app changes. That cost
is paid once whatever 2.0 contains, so 2.0 should carry every breaking change
the framework needs — and nothing that could ship in a 2.x minor.

What v1 has accumulated, measured on v1.78:

- **Surface.** The root package exports ~220 names from 81 files: the app,
  registration, config loading, a config store, dotenv, dev state, a deployment
  manifest (`Declare*`, `DatabaseSpecFor`), extension plumbing and
  test hooks (`ClearConfigStoreForTest`, `InstallConfigStore`,
  `InspectHandlerForExt`, `AppFromGin`).
- **Ten ways to register a handler.** `NewXxx` constructors with `Params[T]`,
  method expressions, `Arg` scalars, `AsCRUD`, `AsRestHandler`, `Controller`,
  `Resource`, `inertia.Resource`, `NewRouter`/`Include`, and `//@` annotations.
  Op names come from stripping a `New` prefix — a rule users have to learn.
- **Inconsistent behaviour across transports.** `validate:` tags are enforced on
  GraphQL and not on REST. Errors map through `MapCRUDError`, `ErrForbidden`,
  `nexus.Errors` and `Envelope`, each with its own rules.
- **Third-party types in the public API.** `Managed` takes a
  `func(*zap.Logger)`; `RegisterGqlType` takes a `graphql.Input`;
  `Service.MountGraphQL` takes a `*graphql.Schema`; `GraphMiddleware` takes a
  `graph.FieldMiddleware`. Swapping the logger or the GraphQL engine is a
  breaking change today.
- **Defaults that favour compatibility over safety.** `max_body_bytes` is off
  (every JSON handler is an unbounded memory sink); read and write timeouts are
  off; CSRF is off even for cookie-session form apps; an unknown nexus.toml key
  is a warning (`reportUnknownConfigKeys`), so a misplaced `[runtime]` key is
  silently ignored in production.
- **16 `Deprecated:` markers** and retired CLI flags kept alive for migration.
- **Nine Go modules** released by hand in a fixed order (root → `view` →
  submodules → `go install` of the CLI), with proxy-lag workarounds.
- **Generated Go on disk.** `nexus dev` writes `*_templ.go`, `view_gen.go` and
  `view_imports_gen.go` into the tree because gopls cannot read `-overlay` files;
  plain `templ generate` produces different code from viewgen, so an editor's
  templ support compiles a view differently from the app.
- **App-specific names in doc comments** (`app_workers.go`, `db/db.go`) left
  from the framework's extraction.

## Principles

1. **One way.** Each task has one documented API. Alternatives are removed, not
   deprecated.
2. **Same behaviour on every transport.** Validation, errors, auth and IDs
   behave identically on REST, GraphQL, WebSocket, Inertia and views.
3. **Standard library at the edges.** The public API names only stdlib and
   nexus types. Third-party engines sit behind seams, as the router and DI
   container already do.
4. **Safe by default.** Production defaults are the safe ones; opting out is
   explicit and per route.
5. **No generated files the user has to look at.** Generated code exists for the
   compiler and the editor, not in the tree.
6. **Migration is a command.** Everything mechanical is done by
   `nexus migrate v2`; everything else is flagged in the code it affects.

## 1. One handler shape

The canonical handler is a method:

```go
func (s *UserService) CreateUser(ctx context.Context, in CreateUser) (*User, error)
```

- **Op names come from the method name** (`CreateUser` → `createUser`), or from
  `nexus.Op("…")`. The `New`-prefix rule is removed; a free function is named
  by its function name the same way.
- **Grouping** is `nexus.Controller[*T](prefix, gates…)` for REST/page actions
  and `nexus.Module(name, …)` for everything else. `Resource` stays as the
  conventional-actions shorthand on top of `Controller`.
- **Scalars** keep `nexus.Arg` (it is how bare path params bind); a body struct
  keeps merging into the args as in v1.
- **`Params[T]`** stays for handlers that need more than ctx and args, but is no
  longer the documented default.
- **Removed:** `NewXxx`-constructor handlers (a constructor returning a handler
  closure), `AsCRUD`, `AsRestHandler` (raw handlers take `*httpx.Ctx` via
  `AsRest` as in v1), and `NewRouter`/`Include` as a separate concept from
  `Module` — a router is a module with a prefix.
- **Annotations map 1:1.** Every `//nexus:` directive (section 11) produces exactly one Go call
  from this section; docs/guide/controllers.md keeps the table.

**Decision:** method handlers are the one shape. The codemod rewrites
`NewXxx(svc, p Params[T]) (R, error)` to `(s *Svc) Xxx(ctx, in T) (R, error)` when
the body only uses `p.Context` and `p.Args`, and flags the rest.

## 2. One error model

```go
return nil, nexus.Err(nexus.NotFound, "user not found")
return nil, nexus.Invalid().Field("email", "already taken").Global("…")
```

- `nexus.Error{Code, Message, Fields, Cause}` with codes `Invalid`,
  `Unauthenticated`, `Forbidden`, `NotFound`, `Conflict`, `TooMany`,
  `Unavailable`, `Internal`. `errors.Is`/`As` work through `Cause`.
- **One mapping table per transport:** REST status + `{message, errors}` body;
  GraphQL `extensions.code` + field map; WebSocket error envelope; Inertia flash
  + 303 back for writes and `ErrorPage` for visits; views `view.Errors(ctx)`.
- **Validation runs on every transport**, REST included, and produces an
  `Invalid` error with per-field messages.
- `Envelope` stays: it is an app-owned wire contract, and it receives the
  `nexus.Error`.
- **Removed:** `MapCRUDError`, `ErrForbidden` (→ `nexus.Forbidden`), and
  `nexus.Errors`/`NewErrors` (→ `nexus.Invalid()`).

**Decision:** adopt. Unknown errors map to `Internal` with the message hidden in
production and shown under `nexus dev`.

**As built (stage 2):** the invalid code is `nexus.InvalidInput` (wire
`INVALID_INPUT`) — `Invalid` is taken by the `nexus.Invalid()` builder in the
same package. A `Code` is itself an error, so `errors.Is(err, nexus.NotFound)`
matches and `return nil, nexus.Forbidden` works. `nexus.ErrorOf` / `CodeOf` map
any error; `nexus.WriteError` writes one on a raw `*httpx.Ctx`; `nexus.Validate`
checks `validate:` tags (also `int=min|max`). Middleware rejections
(`rc.Reject`) render through `middleware.ErrorBody`, which nexus points at the
same table; on GraphQL they surface as `middleware.Rejection`. The boot-time
option formerly named `nexus.Error(err)` is `nexus.FailBoot(err)`, since
`nexus.Error` is now the type. The `ErrCRUD*` sentinels stay, as `*nexus.Error`
values (`ErrCRUDValidation` is a 422 now).

## 3. A smaller root package

A Go package is one directory, so a file can leave the root only when its
code doesn't depend on the root's unexported internals — and code built on
`nexus.Option` can't leave at all, because `Option`'s method is unexported so
that only nexus can implement it. That splits the v1 root in two: groups that
move out as packages, and the core (the `App`, registration, routing options,
handler reflection, transports, the deployment manifest's `App` methods) that
stays in `nexus` and is consolidated into fewer, plainly named files.

| Package | Takes from the v1 root (as built) |
|---|---|
| `nexus` | App, `Boot`/`Run`, `Module`, `Provide`/`Supply`/`Invoke`, `As*`, `Controller`/`Resource`, `Op`/`Arg`/`Describe`/`HideFromDashboard`/`WithIcon`, `NewScoped`, `IfDev`/`IfNotDev`, extension registration (built on `Option`), the error model, `Lifecycle`/`Hook` |
| `nexus/config` | the runtime config types (`Config` → `config.Runtime`, `ServerConfig` → `config.Server`, … `StoreConfig` → `config.Stores`, `Listener`/`ListenerScope`), the loader (`LoadConfig` → `config.Load`, `config.Read`/`Parse`/`File`), `Get`/`MustGet`, `BindConfig` → `config.Bind`, `HasConfig` → `config.Has`, `OnConfigChange` → `config.OnChange`, `ConfigVersion` → `config.Version`, the store (`InstallStore`, `UpdateStore`, `ResetForTest`), dotenv (`config.LoadDotenv` / `RequireDotenv`, returning errors), `EnvVars`, `DatabaseSpec`, `LintRuntimeFile` → `config.LintFile`, `ConfigError` → `config.Error` |
| `nexus/dev` | `PreserveDev` → `dev.Preserve`, `PreserveDevJSON` → `dev.PreserveJSON`, `DevStateDir` → `dev.StateDir`, `DevState` → `dev.State`, `IsDev` → `dev.Enabled`, `NexusDevEnv`/`NexusDevRootEnv` → `dev.Env`/`dev.RootEnv` |
| `nexus/notify` | `Notifier` → `notify.Notifier`, `NewNotifier` → `notify.New`, `Bus` → `notify.Bus` |
| `nexus/resource` | `Cache` → `resource.Cache` (it sits below both config and the root) |
| `nexus/manifest` | `DeclareEnv`, `DeclareEnvList`, `DeclareService`, `DeclareVolume`, `DatabaseSpecFor` (pending: they are `App` methods today) |
| `frontend/vitehot`, `frontend/vitemanifest`, `resource/connlog` | the Vite hot-file and manifest readers and the connection-state logger, public so the CLI and submodules can use them without reaching into `internal/` |
| `internal/…` | `bootui` (the boot diagnostic block), `extnames` (registered extension names for the lint), `devreload` (nexus dev live reload), test hooks and inspection helpers; `AppFromGin` is removed |

**Decision:** adopt the split. The target is under 80 exported names in `nexus`
and no root file whose code could live in a package.

## 4. Strict, typed config

- **Unknown or misplaced keys fail boot**, with the file position and a
  did-you-mean (`environment` at the top level → `[runtime] environment`). The v1
  reason for warning — "a block this binary has no decoder for" — is handled by
  extensions declaring their sections; an undeclared `[extensions.x]` block is
  the error.
- **Custom sections** keep working through `config.Get`; an app declares its own
  sections with `config.Section[T]("mail")`, which decodes into a typed struct
  and joins the strictness check.
- `nexus config check` validates a file (CI), and nexus publishes a JSON schema
  for nexus.toml so editors complete and validate keys.

**Decision:** adopt. `nexus migrate v2` moves misplaced keys it recognises.

## 5. Standard library at the edges

- **Logging is `log/slog`.** `App.Logger()` returns `*slog.Logger`; `Managed`
  takes `func(*slog.Logger)`; `extension/cache`'s `Manager.Logger()` likewise.
  The dev log formatter reads slog JSON. Apps that want zap's encoder wrap a
  zap core in an `slog.Handler` and pass it to `WithLogger`; nexus links no zap.
- **GraphQL goes behind a seam.** No graphql-go type appears in the public API:
  `RegisterGqlType` takes a Go type (reflected like handler args);
  `MountGraphQL` and `GraphMiddleware` take nexus types. graphql-go remains the
  engine for 2.0; the seam lets 2.x replace it (a faster executor, persisted
  queries) without a major version.
- **Traces export to OpenTelemetry.** The dashboard's trace ring buffer stays;
  an OTLP exporter is a config block, off by default.

**Decision:** adopt all three. The GraphQL engine swap itself is out of scope
for 2.0.

## 6. Safe defaults

| Setting | v1 default | v2 default |
|---|---|---|
| `max_body_bytes` | off | 32 MB; per-route `nexus.MaxBody(n)` |
| `read_header_timeout` | Go's (none) | 10 s |
| `read_timeout` / `write_timeout` | off | off globally; per-route `nexus.Timeout(d)` (uploads, SSE and downloads stay unbounded unless set) |
| CSRF | off | on when cookie sessions, Inertia or view forms are in use; token APIs unaffected |
| Security headers | on | on (unchanged) |
| `/__nexus` | off in production | off in production (unchanged) |

**Decision:** adopt. Each changed default is listed in the migration notes with
the one-line opt-out.

## 7. Templ views as a first-class citizen

`view` folds into the root module (`nexus/view`). It already imports root
internals (`internal/vitehot`, `internal/vitemanifest`), which is why it must be
tagged after the root today.

### 7.1 `nexus lsp` — one generator for the compiler and the editor

- The CLI serves an LSP for `.templ` files using viewgen's output, replacing
  templ's own LSP for nexus projects (the nexus-zed and IntelliJ plugins already
  launch a nexus LSP).
- For `.go` files it sits in front of gopls and opens viewgen's generated files
  as unsaved buffers (`didOpen`). gopls accepts in-editor overlays over LSP,
  unlike `go build -overlay` files — tested on v1.78: with the files only in an
  `-overlay`, `go test` passes but gopls fails with `stat …: no such file or
  directory`.
- With the editor served by the LSP and builds by the overlay, **generated view
  files leave the disk.** `nexus dev` stops writing them.
- Diagnostics cover nexus rules: `view.Send` to a method that isn't an event, a
  malformed `//nexus:page`, shard gates that disagree, an island with no component
  file.

### 7.2 Pages are endpoints

`//nexus:page`, `view.Live` and islands appear in `/__nexus` and the architecture
graph under their module, with their events (and argument types), injected
services and gates. Each live event is a trace span with its render time and
patch size. A page's `auth.Requires` feeds `auth.OpGates`, so navigation and
access come from one declaration.

### 7.3 A component kit: `nexus/view/ui`

Button, Field, Select, Tabs, Dialog, Dropdown, RowActions, DataTable (paging,
search, row click, action menus), Toast, Loader and PageHeader, with their
runtime pieces (loader overlay, toasts, hotkeys, copy-link) in the view runtime.
`view.Send(x.Run).Loading("preview")` replaces app-written loader wrappers.
`nexus add ui <component>` vendors a component for apps that want to own it.

### 7.4 Documented form semantics

The rules the runtime follows become documented and browser-tested guarantees:
a field's value belongs to the user until the server's value changes; a focused
field is never overwritten; a `<select>` follows the server's chosen option;
a textarea follows the server's value; a form resets after a successful submit.
`view.Value(v)` marks a field server-owned explicitly.

### 7.5 `viewtest`

```go
p := viewtest.Mount[*Builder](t, app, viewtest.As("staff"))
p.Fill("title", "Sales").Click("#run").Wait()
p.Expect("#save").Enabled()
```

Runs the real runtime (morph, events, forms) in goja without a browser;
`viewtest.Browser` drives a real one for layout checks.

**Decision:** adopt 7.1–7.5. 7.1 starts with a spike proving gopls accepts the
generated buffers in Zed and GoLand; if it doesn't, generated files stay on disk
(gitignored) and the rest of section 7 is unaffected.

## 8. Tooling

- **`nexus test` / `nexus vet`** wrap `go test` / `go vet` with the same overlay
  as `nexus build` (handler codegen and views), so no generated file is needed on
  disk for any go command the project runs. `GOFLAGS=-overlay=…` is the
  mechanism, verified on v1.78.
- **`nexus release`** performs the multi-module release: CHANGELOG check, root
  tag, submodule `go get` + tidy + build + tags in dependency order, push, and the
  CLI install check, with the direct-proxy settings the hand process needs.
- **`nexus doctor`** checks Go, Node and the package manager, the Tailwind CLI,
  nexus.toml and the frontend dir.
- **`nexus migrate v2`** — see Migration.

**Decision:** adopt.

## 11. Annotations are Go directives: `//nexus:`

Annotations change from `//@rest GET /users/:id` to `//nexus:rest GET /users/:id`,
the form Go reserves for tool directives (`//go:generate`, `//go:embed`,
`//lint:ignore`).

```go
// GetUser returns one user.
//
//nexus:rest GET /users/:id
//nexus:auth Requires view_user
func (s *UserService) GetUser(ctx context.Context, id int64) (*User, error)
```

Why — checked against Go's own tools on v1.78:

- **gofmt leaves `//nexus:` lines as written.** A line matching
  `//[a-z0-9]+:[a-z0-9]` is a directive: gofmt inserts no space and keeps the
  directives' relative order, moving them below the doc prose. `//@rest` is
  rewritten to `// @rest`, which is why v1 has to accept both spellings.
- **Directives stay out of documentation.** go/doc and `go doc` drop directive
  lines; a v1 `//@rest GET /x` above "X does x." renders as `@rest GET /x X does
  x.` in the package docs.
- **The namespace says who reads it.** `//nexus:` cannot collide with another
  tool's `@`-annotations (swag's `// @Summary`, for one), and grep, linters and
  editors can tell nexus directives apart.

The grammar is unchanged; only the prefix moves:

| v1 | v2 |
|---|---|
| `//@rest GET /p`, `//@query`, `//@mutation`, `//@subscription` | `//nexus:rest GET /p`, `//nexus:query`, … |
| `//@ws`, `//@worker`, `//@job`, `//@provide` | `//nexus:ws`, `//nexus:worker`, `//nexus:job`, `//nexus:provide` |
| `//@auth`, `//@session`, `//@use` | `//nexus:auth`, `//nexus:session`, `//nexus:use` |
| `//@controller`, `//@router`, `//@on`, `//@page` | `//nexus:controller`, `//nexus:router`, `//nexus:on`, `//nexus:page` |
| package `//@module`, `//@path`, `//@routeprefix` | `//nexus:module`, `//nexus:path`, `//nexus:routeprefix` |
| custom `//@inertia.Page`, `//@pkg.Func` | `//nexus:inertia.Page`, `//nexus:pkg.Func` |
| `//@page` above a templ component | `//nexus:page` (viewgen reads the same prefix) |

What changes with it:

- **Scanner.** deco's scanner (used by `nexus generate handlers`, the dev and
  build overlays) and viewgen accept the `//nexus:` prefix; error messages and
  did-you-mean suggestions use it.
- **Editor plugins.** nexus-zed and the IntelliJ plugin highlight, complete and
  diagnose `//nexus:` directives.
- **v2 rejects `//@` and `// @`** with an error naming the file and line and
  pointing to `nexus migrate v2`. The v1.80 bridge release accepts both prefixes
  and warns on `//@`.
- **Codemod.** `nexus migrate v2` rewrites every `//@x` and `// @x` annotation,
  in `.go` and `.templ` files, to `//nexus:x`, then runs gofmt.

**Decision:** adopt.

## 12. Assembling an app

A real v1 `main` (a production app, trimmed):

```go
opts := []nexus.Option{nexus.MustLoadDotenv()}
cfg := nexus.MustLoadConfig()
cfg.SDK = true
shell, _ := webFS.ReadFile("web/dist/index.html")
cfg.Middleware.Global = append(cfg.Middleware.Global, modules.GlobalMiddleware(shell)...)
opts = append(opts, nexus.MustLoadExtensions()...)
opts = append(opts, edge.Foundation()...)
opts = append(opts,
	nexus.ServeFrontend(webFS, "web/dist"),
	inertia.Module(inertia.Config{ErrorPage: "Error"}),
)
opts = append(opts, modules.Shared()...)
opts = append(opts, resources.DatabaseOptions()...)
opts = append(opts, nexus.Invoke(resources.EnsureReportRole))
opts = append(opts, nexus.Invoke(resources.EnsureIndexes))
// … 20 more appends: providers, workers, modules
nexus.Run(cfg, opts...)
```

What forces it into this shape:

- **`Boot` can't be used.** It loads nexus.toml and extensions, but not `.env`,
  and offers no way to add app-level middleware — so the app drops to
  `MustLoadConfig` + `MustLoadExtensions` + `Run` and repeats what `Boot` does.
- **App middleware is a `Config` field, not an option.** `Middleware.Global` is
  set by mutating `cfg`, so middleware can't come from a module and can't take
  DI dependencies.
- **The frontend document is read by hand.** `ThemeHead` needs `index.html`, so
  main reads it from the embed — which is stale under `nexus dev`, where pages
  render into the document Vite serves. The app already owns that document
  (`App.FrontendDocument`); middleware can't reach it.
- **Config set in code.** `cfg.SDK = true` belongs in nexus.toml.
- **Order is carried by position.** `EnsureReportRole` and `EnsureIndexes` must
  run after the databases and before modules use them; that holds only because
  of where the `Invoke` lines sit. Compress must wrap `ThemeHead` — again by
  slice position.
- **Helpers return `[]nexus.Option`**, so every bundle needs `append(opts, x...)`
  instead of being an option itself.
- **`middleware.Middleware.Gin`** is the REST field's name although gin is no
  longer the router; `ClientIP` is re-implemented by the app although
  `nexus.ClientIPFromCtx` exists.

### The v2 shape

```go
//go:embed all:web/dist
var webFS embed.FS

func main() {
	nexus.Boot(
		nexus.Frontend(webFS, "web/dist"),
		inertia.Module(inertia.Config{ErrorPage: "Error"}),
		edge.Module,
		resources.Module,
		services.Module,
		govclients.Module,
		modules.Module,
	)
}
```

```toml
[runtime]
sdk    = true
dotenv = [".env"]        # loaded first; ${VAR}s in this file see it
```

**1. `Boot` is the only entry.** It loads `dotenv` files (`[runtime] dotenv`,
default `[".env"]`, missing files skipped unless listed with `!`), then
nexus.toml, then the extensions. `Run(cfg, …)` stays for apps that build
`Config` in Go, but nothing in the docs needs it.

**2. Every bundle is one `nexus.Option`.** Helpers return `nexus.Option`
(`nexus.Module` or `nexus.Options`), never `[]nexus.Option`; `Boot` takes them
flat. A module declares its own providers, workers, middleware and setup steps:

```go
var Module = nexus.Module("resources",
	db.BindFromConfig[MainDB]("main", db.WithDefault()),
	mail.BindFromConfig[Mailer]("smtp"),
	nexus.Provide(NewStorage, NewCDCRuntime),
	nexus.Setup(EnsureReportRole, EnsureIndexes),
	nexus.AsWorker("cdc", StartCDC),
)
```

**3. App middleware is an option, and it is DI-constructed.**

```go
var Middleware = nexus.Middleware(
	edge.Compress,          // middleware.Middleware value
	admin.ThemeHead,        // func(doc *nexus.Document) middleware.Middleware
	auth.RequestedTarget,
)
```

- `nexus.Middleware(...)` takes values or constructors; a constructor's
  parameters come from DI, like any provider.
- **Placement is declared, not positional.** A middleware sets `Stage`:
  `middleware.Edge` (outermost: compression, client IP, request IDs),
  `middleware.Session`, `middleware.Auth`, `middleware.App` (default). Within a
  stage, declaration order holds across modules. Compress declares `Edge`, so
  it wraps `ThemeHead` wherever either is registered.
- `Config.Middleware.Global` is removed; the dashboard's middleware view lists
  app middleware by stage.
- `middleware.Middleware.Gin` is renamed `HTTP`.
- Client IP is built in (`nexus.ClientIP(ctx)`, honouring trusted proxies from
  `[runtime.server] trusted_proxies`); apps stop re-implementing it.

**4. The frontend document is a DI value.** `nexus.Frontend(fs, root)` (renamed
from `ServeFrontend`) provides `*nexus.Document`: the page shell in production,
and the live document from Vite's hot file under `nexus dev`. Middleware, Inertia
and views take it as a parameter instead of reading the embed.

**5. Startup work has named phases instead of positions.**

| Phase | Runs | For |
|---|---|---|
| `nexus.Provide` | lazily, when a value is first needed | constructors |
| `nexus.Setup(fns…)` | after resources start, before listeners open; in declaration order; an error aborts boot | migrations, roles, indexes, seeds, backfills |
| `nexus.OnStart` / `nexus.OnStop` | lifecycle, as v1 `Lifecycle` hooks | connections, background loops |
| `nexus.AsWorker` | after listeners open | long-running work |

`nexus.Invoke` stays for eager construction, but the docs stop using it for
startup work; `Setup` is what says "this must finish before we serve".

**Decision:** adopt 1–5. The codemod turns a `MustLoadConfig` + `Run` main into
`Boot` when the only `cfg` edits are keys nexus.toml can hold (they move to the
file), rewrites `cfg.Middleware.Global = append(…)` into `nexus.Middleware(…)`,
and rewrites `Invoke` of functions returning only `error` to `Setup`, flagging
each for review.

## 13. Authentication

Designed separately in [v2-auth.md](v2-auth.md): six concepts (Scheme, Users,
Identity, Gate, Area, Policy), one `auth.Module` configured under `[auth]`,
deny-by-default gates written `//nexus:auth …`, the identity read the same way
on every transport and in jobs, and areas that bind a path prefix to user
kinds, login pages and redirects.

## Migration

1. **v1.80 — bridge release.** Every API removed or renamed in 2.0 logs one
   warning at boot (under `nexus dev`) and is reported by `nexus lint`, naming
   its replacement. Changed defaults are announced the same way when the app
   relies on the v1 value (e.g. no `max_body_bytes` set).
2. **`nexus migrate v2`.** Rewrites imports to `/v2`, moves renamed symbols to
   their packages, applies the 1:1 replacements in section 9, rewrites simple
   `NewXxx` handlers to methods, converts `nexus.Errors` and `ErrForbidden`, and
   moves misplaced nexus.toml keys, and rewrites `//@` annotations to
   `//nexus:` (11). Anything it cannot rewrite gets a
   `// TODO(nexus v2): …` comment at the call site.
3. **Proving ground.** A production nexus app is migrated with the codemod and
   must build, pass its tests and serve before v2.0.0 is tagged.
4. **v1 maintenance.** Security fixes on a `v1` branch for six months after
   v2.0.0.

## Stages

Each stage leaves `main` releasable as a v2 pre-release (`v2.0.0-alpha.N`).

1. **Mechanical.** Module path, root split (3), removals (9), slog (5),
   `//nexus:` directives (11), comment cleanup. Builds the codemod as it goes.
2. **Behaviour.** Error model (2), handler shape (1), strict config (4), safe
   defaults (6), validation everywhere, app assembly (12).
3. **Views.** Fold `view` in, `nexus lsp` spike then build (7.1), form
   semantics and `viewtest` (7.4–7.5), component kit (7.3), dashboard pages
   (7.2). Can run in parallel with stage 2.
4. **Tooling and seams.** `nexus test/vet/release/doctor` (8), GraphQL seam and
   OTel export (5).
5. **Release.** Bridge release v1.80 (can ship as soon as stage 1's list is
   final), codemod complete, proving-ground migration, v2.0.0.

## Decisions on the open questions (2026-10-04)

- **Handler constructors:** removed. Per-handler state moves to a service
  field; `nexus migrate v2` rewrites simple `NewXxx` handlers to methods and
  flags the rest with `// TODO(nexus v2)`.
- **`Params[T]`:** kept as the escape hatch; `(ctx, in T)` is the documented
  default and the codemod leaves `Params[T]` alone.
- **Strict config:** unknown keys in known sections fail boot, and so does any
  section nobody declared — an `[extensions.x]` block without a registered
  decoder, or an app section not declared with `config.Section[T]`.
- **CSRF:** on automatically when cookie-based auth or forms are in use
  (sessions, cookie schemes, Inertia, view forms); token-only APIs unaffected.
- **v1 support window:** open.
