# Preparing for 2.0

nexus 2.0 is a major version: the module path becomes
`github.com/paulmanoni/nexus/v2`, and the release removes or renames the v1 APIs
that grew alternatives, moves configuration and dev helpers out of the root
package, and switches a few defaults to the safe value. `nexus migrate v2` does
the mechanical part of the move.

**v1.80 is the bridge release.** It changes no behaviour. It tells you, while
you are still on v1, everything 2.0 will change in your app, so the migration
holds no surprises:

- **At boot, under `nexus dev`**, the app prints one block listing each v1 API
  it actually used, where it was called, and what 2.0 has instead.
- **`nexus lint --v2`** lists the same things statically, by file and line,
  including code the app didn't reach while you were running it.
- **Annotations** read in the 2.0 spelling, `//nexus:rest`, as well as `//@rest`.
  You can switch file by file.

## The boot notice

```text
nexus: v2 notice — this app uses 4 v1 API(s) that nexus 2.0 removes or renames (dev only; …):
  - op "searchNotes" from NewSearchNotes  (notes/handlers.go:47)
      v2: the op is named after the handler as written, "newSearchNotes" — add nexus.Op("searchNotes") to the registration (or //nexus:use nexus.Op("searchNotes") above an annotated handler) to keep the wire name
  - nexus.Run with a nexus.Config  (main.go:32)
      v2: nexus.Config is config.Runtime (package nexus/config); nexus.Run stays, but nexus.Boot with settings in nexus.toml is the documented entry
  - [runtime.server] max_body_bytes unset (v1: no limit)
      v2: request bodies are capped at 32 MB by default; set [runtime.server] max_body_bytes (or nexus.MaxBody per route) if the app accepts larger ones
  - nexus.PreserveDev  (notes/store.go:33)
      v2: dev.Preserve (package nexus/dev), same arguments
  Silence with NEXUS_V2_NOTICES=0.
```

- It appears only under `nexus dev` (`NEXUS_DEV=1`). A production binary records
  nothing; each deprecated call costs one atomic load there.
- Each API is reported once per process. A use that happens after boot — the
  first request to call `nexus.MapCRUDError`, say — prints on its own, once.
- Calls made by nexus's own packages don't count: only your code is reported.
- `NEXUS_V2_NOTICES=0` silences the block.

## `nexus lint --v2`

```text
$ nexus lint --v2
main.go:15: v2: nexus.MustLoadConfig → config.MustLoad — or nexus.Boot, which loads nexus.toml itself
main.go:21: v2: nexus.ServeFrontend → nexus.Frontend (same arguments; also provides *nexus.Document)
users/handlers.go:13: v2: uri:"id" → path:"id" (2.0 binds path params from the path tag only)
users/handlers.go:46: v2: //@query → //nexus:query (2.0 reads only Go's directive form; v1.80 reads both)
users/handlers.go:47: v2: op "searchUsers" from NewSearchUsers: 2.0 names it "newSearchUsers" (the handler as written) — add //nexus:use nexus.Op("searchUsers") to keep the wire name
nexus.toml:1: v2: 2.0 fails boot on this key: "environment" sits at the top level of the file, … — did you mean [runtime] environment?
nexus.toml:6: v2: [billing] is an app section: 2.0 fails boot on sections nobody declared — declare it with config.Section[T]("billing")

nexus lint --v2: 7 finding(s) in 3 file(s). …
```

It takes a project directory (default `.`), honours `.nexusignore`, skips
generated files and nested modules, and always exits 0. `--json` prints the
findings for tooling.

## What 2.0 changes

| v1 | 2.0 |
|---|---|
| `nexus.Config`, `ServerConfig`, … `StoreConfig` | `config.Runtime`, `config.Server`, … `config.Stores` (package `nexus/config`) |
| `LoadConfig`, `MustLoadConfig`, `Get`, `MustGet`, `BindConfig`, `HasConfig`, `OnConfigChange` | `config.Load`, `config.MustLoad`, `config.Get`, `config.MustGet`, `config.Bind`, `config.Has`, `config.OnChange` |
| `MustLoadDotenv()`, `LoadDotenvIfPresent()` | `Boot` loads `.env` itself: `[runtime] dotenv = [".env"]` (`"!.env"` makes it required) |
| `IsDev`, `PreserveDev`, `PreserveDevJSON`, `DevStateDir` | `dev.Enabled`, `dev.Preserve`, `dev.PreserveJSON`, `dev.StateDir` |
| `NewNotifier`, `Notifier`, `Bus` | `notify.New`, `notify.Notifier`, `notify.Bus` |
| `ServeFrontend(fs, root)` | `nexus.Frontend(fs, root)`, which also provides `*nexus.Document` |
| `Config.Middleware.Global` | `nexus.Middleware(…)`: an option, DI-constructed, ordered by stage |
| `middleware.Middleware{Gin: …}` | `HTTP: …` |
| `AsCRUD[T]` | `nexus.Resource[T](prefix)` with Index/Show/Create/Update/Destroy |
| `AsRestHandler` | `AsRest` with a handler that takes `*httpx.Ctx` |
| `nexus.Errors` / `NewErrors()` | `nexus.Invalid().Field(…).Global(…)` |
| `MapCRUDError`, `ErrForbidden` | `nexus.ErrorOf` / `CodeOf`, `nexus.Forbidden` |
| `nexus.Error(err)` (boot option) | `nexus.FailBoot(err)` — `nexus.Error` becomes the error type |
| `UseVolume` | `DeclareVolume` |
| `ClientIPFromCtx`, `WithClientIP` | `nexus.ClientIP(ctx)`; the framework records the address |
| `AppFromGin`, `RegisterGenerateDriver` | removed |
| `auth.Describe` | `auth.InspectExtractor` |
| `auth.LoginEndpoint`, `auth.LogoutEndpoint` | `auth.Config.Endpoints` |
| `uri:"id"` tags | `path:"id"` |
| a `*zap.Logger` provider; `Managed(func(*zap.Logger) …)` | `log/slog`: `App.Logger()` is a `*slog.Logger`; replace it with `nexus.WithLogger` |
| `//@rest GET /x` annotations | `//nexus:rest GET /x` |

### Op names

v1 drops a `New` prefix when it names an op: `NewListPets` serves the GraphQL
field `listPets`. 2.0 names an op after its handler as written, so the same
handler serves `newListPets`. To keep a wire name, name it explicitly — this
works on v1 today:

```go
nexus.AsQuery(NewListPets, nexus.Op("listPets"))
```

```go
//nexus:query
//nexus:use nexus.Op("listPets")
func NewListPets(svc *PetService, p nexus.Params[ListArgs]) ([]Pet, error)
```

`nexus migrate v2` adds these for you.

### Annotations are Go directives

2.0 reads annotations only in Go's directive form, `//nexus:x` — the form
gofmt leaves unspaced (it rewrites `//@rest` as `// @rest`) and `go doc` keeps
out of rendered documentation. v1.80 reads both:

```go
// GetUser returns one user.
//
//nexus:rest GET /users/:id
//nexus:auth Requires view_user
func (s *UserService) GetUser(ctx context.Context, id int64) (*User, error)
```

The grammar after the prefix is unchanged, including type directives
(`//nexus:controller`), package directives (`//nexus:module`, `//nexus:path`),
custom decorators (`//nexus:inertia.Page`) and `//nexus:page` above a templ
component. Write `//nexus:` with no space after the slashes; an unknown
`//nexus:` keyword is an error.

### nexus.toml is strict

v1 warns about a key nothing reads; 2.0 fails boot on it, and on any
top-level section nobody declared. Move misplaced keys where the warning says
(`nexus migrate v2` does it for the ones it recognises), and declare your own
sections with `config.Section[T]("name")` after upgrading.

### Changed defaults

| Setting | v1 | 2.0 |
|---|---|---|
| `[runtime.server] max_body_bytes` | no limit | 32 MB; per route `nexus.MaxBody(n)` |
| `read_header_timeout` | none | 10 s |
| CSRF | off | on when cookie sessions, Inertia or view forms are in use |

The boot notice and the lint report an unset `max_body_bytes`.
